# Repository Guidelines

## Project Structure & Module Organization
Keep runtime code inside `src/`, grouping files by responsibility: `src/config` (shared env/logging), `src/database`, `src/http`, `src/proxy`, `src/ratelimit`, and `src/routes`. Use the TypeScript path aliases (`@config/*`, `@database/*`, `@http/*`, `@proxy/*`, `@ratelimit/*`, `@routes/*`) instead of deep relative paths. Keep TypeScript outputs in `dist/` (generated by `npm run build`) and infrastructure artifacts (`Dockerfile`, `docker-compose.yml`, `.env.example`) at the project root.

## Build, Test, and Development Commands
- `npm install` — install app and tooling dependencies.
- `npm run dev` — start the Express server with `tsx` watch for rapid iteration.
- `npm run lint` / `npm run format` — run ESLint and Prettier across `src/`.
- `npm run build` — emit compiled JavaScript to `dist/`.
- `npm run start` — execute the compiled server (ES modules via Node 20).
- `docker compose up --build` — build the container image and start MongoDB, Redis, and the gateway service together (required before hitting the admin API).
- `npm run test` — run the Jest suites (unit + integration);
- `npm run test:watch` — interactive test mode during development.
- `npx tsc -p tsconfig.test.json` — optional type-check for files under `test/`.

## Proxy & Route Management
- Admin endpoints live under `/admin/routes`; mutations automatically invalidate the in-memory route cache (`src/proxy/route.cache.ts`).
- Patterns leverage `path-to-regexp`; higher `priority` wins when multiple routes match.
- `rateLimit` overrides can be supplied per route (`limit`, `windowSec`) or removed by patching with `null`.
- Gateway middleware proxies everything else; remember to keep health checks (`/health`) lightweight for liveness probes.

## Rate Limiting Guidelines
- Redis-backed token bucket lives in `src/ratelimit/rate-limiter.ts`; avoid duplicating Lua logic elsewhere—expose helpers if new consumers appear.
- Defaults come from `RATE_LIMIT_DEFAULT_LIMIT` and `RATE_LIMIT_DEFAULT_WINDOW_SEC`; document any new env flags in `.env.example` and README.
- Route cache (`resolveRoute`) surfaces overrides; always pass both `limit` and `windowSec` when adding an override to keep validation simple.
- Gateway emits standard headers (`x-ratelimit-*`, `retry-after`); preserve them if adding more middleware or response transforms.

## Usage Logging & Analytics
- Usage entries are buffered through `enqueueUsageLog` and flushed asynchronously; call `flushQueue` on shutdown whenever adding new exit paths.
- The `usage_logs` collection stores raw events; use `getUsageSummary` / `listUsageLogs` helpers for admin endpoints rather than inlining aggregation.
- Keep batching parameters (`USAGE_LOG_BATCH_SIZE`, `USAGE_LOG_FLUSH_INTERVAL_MS`) configurable; update docs if defaults change.
- When extending analytics, prefer Mongo aggregation pipelines over in-memory processing to keep memory usage predictable.

## Plugin Framework
- Plugin modules live under `plugins/` (default configurable via `PLUGINS_DIR`); each exports `name`, `version`, and optional hook factories.
- Prefer configuration-driven hooks: route definitions supply `plugins.pre|post|error` arrays with `{name, config}` objects.
- All hooks must resolve within `PLUGIN_TIMEOUT_MS`; wrap long operations with safe guards to avoid blocking the request lifecycle.
- Use `loadPlugins` (server bootstrap) and `resolvePluginsForRoute` to hydrate routes; register new plugins via admin APIs by referencing their `name`.

## Coding Style & Naming Conventions
Write TypeScript targeting ES2020 with 2-space indentation and single quotes (JSON excluded). Prefer PascalCase for classes (`GatewayServer`), camelCase for functions and variables, and kebab-case for file names when multiple words are needed. Keep modules focused; expose shared helpers via small barrel files to avoid deep relative paths. Run linting/formatting before opening a PR.

## Testing Guidelines
Introduce Jest as features land. Co-locate unit tests with source files using the `*.spec.ts` suffix. Reserve a top-level `test/` directory for integration and e2e suites that exercise the Docker Compose stack (Express + MongoDB + Redis). Maintain regression coverage around proxy behavior, authentication, and rate limiting once implemented, aiming for ≥80% coverage on critical modules.

## Commit & Pull Request Guidelines
Follow Conventional Commits (`feat:`, `fix:`, `chore:`, optional scopes) with imperative summaries. Squash commits unless reviewers request otherwise. PR descriptions must outline the change, list executed checks (e.g., `npm run lint`, `npm run build`, `docker compose up --build` smoke test), and include HTTP evidence (curl output, screenshots) when altering request flows. Wait for CI to pass before requesting review.

## Security & Configuration Tips
Store secrets in git-ignored `.env` variants and document every environment flag inside `.env.example`. Keep container images minimal, rotate API keys and JWT secrets regularly, and avoid hard-coding credentials in sample plugins or tests. Audit rate-limiter defaults whenever new upstream integrations are added.
